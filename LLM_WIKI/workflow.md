# Как работать с репозиторием

## Ветки

| Ветка | Роль |
|---|---|
| `staging` | **Рабочая ветка.** Сюда идут все изменения через PR. Самая свежая. |
| `main`, `dev` | Застыли в феврале–марте 2026, не использовать как базу. |
| `feat/*`, `fix/*`, `docs/*` | Ветки задач, всегда от `staging`, PR в `staging`. |
| `copilot/*` | Старые ветки Copilot-агента, не трогать. |

Как `staging` попадает в прод — см. [open-questions.md](open-questions.md) (пока неизвестно, какая ветка/образ на прод-сервере).
CI-сборка Docker (`.github/workflows/docker-*.yml`) настроена на `main`/`dev` и публикует образы апстрима (`fr1ngg/...`),
для Ulya она не деплой.

## Правила, что требует согласия владельца

Без явного «да» владельца **нельзя**:

- пушить в `staging` напрямую, мерджить PR, открывать PR (спроси, если не попросили явно);
- трогать прод: сервер, прод-БД, `.env` прода, панель Remnawave;
- запускать SQL на прод-БД (в т.ч. `bot/models/*.sql`);
- массовые рассылки, сообщения пользователям, любые действия от имени бота;
- менять цены, тарифы, платёжные настройки.

Можно без спроса: создать свою ветку, коммитить в неё, пушить свою ветку, гонять тесты локально.

## Проверки перед PR

```bash
uv sync --group dev
uv run ruff format --check .   # CI: .github/workflows/lint.yml, на всех ветках
uv run ruff check .
uv run pytest -v               # или make test
```

Базовая линия тестов на `staging` (октябрь 2026): **88 failed / 446 passed**, все 88 падений старые.
Сравнивай количество до и после своей правки, новых падений быть не должно. Если число изменилось — обнови тут.

Ruff: line-length 120, Python 3.13. В `bot/` встречаются двойные кавычки, в `app/` одинарные — следуй стилю файла.

## Коммиты

- Conventional commits: `feat(scope): ...`, `fix(subscription): ...`, `style(bot): ...`, `refactor(grace): ...`.
- Тело коммита объясняет **почему** и что сломалось (см. `git log` на `staging`, это хороший образец).
  В конце тела: результат тестов («Suite unchanged at 88 failed / 446 passed»).
- Тексты для пользователя добавляй **во все 5 локалей** и в оба места: `locales/*.json` и `app/localization/locales/*.json`
  (см. [architecture.md](architecture.md#локализация)).

## .gitignore — белый список

`.gitignore` игнорирует **всё** (`*`) и разрешает только перечисленное. Новая папка в корне (как эта `LLM_WIKI/`)
не попадёт в git, пока не добавишь `!папка/` и `!папка/**`. Если `git status` не видит твой файл — дело в этом.

## Миграции

Alembic: `migrations/alembic/versions/NNNN_описание.py`, сейчас последняя `0058`. Запускаются сами при старте
(`run_alembic_upgrade` в `main.py`). Исключение: таблицы пакета `bot/` (`bot/models/*.sql`) создаются вручную SQL-скриптом.
